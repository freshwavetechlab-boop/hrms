Phase 1 - Organization foundation

Create the legal and operational base

Complete Organization setup

Open Settings - Organization. Complete Organization, Tax, EPF, ESI, Professional Tax and Labour Welfare Fund tabs. Confirm legal identity before client or payroll setup.

Create or verify the client

The client code is a stable business key used by imports, employee codes, attendance and reports. Search before creating a duplicate.

Map work locations

Create every payroll-relevant branch, office or deployment location. State and GST identity are especially important for PT, LWF and client billing.

Load controlled dropdown masters

Prepare Business Unit, Department, Designation, Work Week, Employment Type, Employee Category, Grade and Cost Center before employee upload.

Phase 2 - Documents and access

Secure storage, permissions and approvals

Configure attachment types and field rules

Define reusable document attributes and map them to employee forms. File constraints, owner rights, verification and versioning are configuration, not free-form upload behaviour.

Verify the active storage mount

Use Security - App Settings - Storage Servers. One server is the default write target. Existing servers remain read-enabled so older files are not lost or duplicated in the UI.

Create least-privilege roles

Keep setup, employee, attendance, payroll run, approval, payment and reporting permissions separable. Assign client scope to non-global users.

Configure PAYRUN.SUBMIT approval

Build payroll approval in the global Workflow module. Locking a draft starts the configured chain; the assigned user decides in My Tasks and the complete trail remains in Workflow History.

Phase 3 - Payroll configuration

Tax, statutory, components and templates

Review the Tax Engine

Publish the financial year and rule version. Maintain slabs, surcharges, final adjustments, declaration sections, HRA rules and source references. Company settings control employee declaration windows.

Review statutory rules

Confirm EPF, ESI, PT and LWF registrations and applicable rules. Professional Tax remains state-wise and effective-dated.

Build salary components

Use stable codes. Derived values should use formulas; residual/balancing components complete CTC; manual/variable components flow through adjustments. Tag PF/ESI/statutory roles correctly because compliance and billing reports consume those identities.

Build the client salary template

Select the client, template name, reference annual CTC and component mix. Verify dependency order and that earnings, deductions and employer benefits reconcile to the intended CTC.

Activate the payslip template

Choose theme, logo/client visibility, YTD and bank visibility, and the approved footer note. Preview before activation.

Phase 4 - Leave and attendance

Make attendance payroll-ready

Create attendance policies

Configure work week, location, department/designation criteria, attendance cycle, payroll report day and employee membership. The selected policy determines the regular payroll roster.

Create leave types

Define paid/unpaid behaviour, entitlement, pro-rata, reset, carry-forward, encashment, negative balance/LOP, half-day, date windows and employee applicability.

Publish the holiday calendar

Maintain year-wise holidays and restricted holidays; apply them globally or to selected work locations.

Set attendance calculation rules

Confirm check-in/out, first/last punch method, half-day/full-day/minimum/maximum hours, regularization window and monthly request limit.

Configure geo-fence only where required

Use work-location or employee scope with latitude, longitude, radius, GPS tolerance, strictness, effective dates, action flags and priority. Test at the actual site before enforcing Strict mode.

Phase 5 - Employee onboarding

Bulk-load, review and complete payroll infotypes

Select the client and prepare the workforce

Download the client template or use Smart Bulk Upload for another Excel/CSV layout. Employee code, work email, client, location and master values must be unique/valid.

Map and review the bulk file

Choose create, update or upsert. Map source columns, resolve identity conflicts, review changes and acknowledge the preview. The import job is started only after the final Import action.

Assign salary and payment data

Open Basic Pay, select the client template and annual CTC, then review the calculated component breakup. Only component types that permit employee overrides are editable. Add a change reason and save the infotype. Complete Payment Details and required Documents before payroll.

Phase 6 - Monthly payroll close

Attendance to approved pay-run

Complete Attendance Review

Select the client, exact attendance policy and payroll period. Review daily cells, payable days and LOP. Resolve missing/invalid rows and save through the background batch job until every employee shows Ready for payroll.

Queue the regular draft

Open Payroll - Regular Run. Confirm client, policy, period, working days, included employees, approved adjustments and estimated cost. Queueing creates saved employee, component, validation and diagnostic records.

Review diagnostics and history

Use Review/Pay History to open the saved run. Correct blocking masters in their source module, then recalculate as supported. Do not hide exceptions with manual values unless the component/process explicitly allows it.

Lock and approve

Reconcile employee count, gross, deductions, employer cost and net payable. Lock Payroll starts PAYRUN.SUBMIT and moves the run to Pending Approval. The assigned approver uses My Tasks; the processor cannot bypass a pending workflow.

Record payment

After bank/payment processing is actually completed, select the employees, payment date and mark them paid. This is an HRMS record of external settlement, not a bank transfer instruction.

Before draftAttendance ready; employees active; salary, bank and statutory identity complete.
Before lockNo blocking validations; totals and variance reviewed; adjustments approved.
Before paymentWorkflow approved; bank file/advice reconciled; external processing confirmed.
Phase 7 - Reports and client billing

Reconcile outputs and prepare billing

Reconcile the Salary Register

Filter the client, pay period and exact pay-run. Compare employee totals with the pay-run summary and export the reviewed view.

Validate statutory reports

PF/ESI/PT/TDS reports depend on salary component statutory identities and employee master values. Reconcile totals before portal uploads or remittance.

Configure client billing

Billing is independent of payroll calculation. Configure effective-dated client/location rules for payroll cost, component/category/statutory sources, fixed charges, commission/service charge and GST. Sort commission after its base lines.

Generate the billing basis

Select the approved pay-run and reconcile Payroll Cost + Employer Statutory + Service Charge + GST to the contract. Export this basis for invoice preparation.

Preview and distribute payslips

Use Payslip Register after approval. Preview employee identity, earnings, deductions, YTD and bank display, then export the PDF. Employee access should follow ESS permissions.

Month-end control checklist

  • Freeze master changes for the payroll cut-off window or document every effective-dated correction.
  • Attendance Review is clean for the same client, period and policy used by payroll.
  • New joiners, exits, transfers, salary changes, adjustments and bank details are reviewed.
  • Payroll diagnostics contain no blocking validation; gross, deduction, net and employer cost variance is explained.
  • PAYRUN.SUBMIT workflow is approved by the configured user; Workflow History is retained.
  • Bank advice/net pay, statutory reports, payslip register and client billing basis reconcile to the approved run.
  • Payment status is recorded only after settlement evidence exists.
Automation and troubleshooting

Safe Playwright operating model

Existing guided journeys already cover foundation, access, workflow, employee upload, attendance readiness and the pay-run lifecycle. Mutating setup tests remain opt-in and pause at Review & Proceed checkpoints. This document generator performs only GET/navigation/UI-open actions; sample-only visuals are fulfilled inside the browser and never written to the database.

cd D:\NewHrms\hrms\playwright-e2e
npm run docs:client-payroll
