# Public careers directory

`/careers` is the anonymous, all-client job board. It is outside `AuthGate` and uses `GET /api/public/recruitment/jobs` plus the existing public organization-brand endpoint. Both board requests omit cookies and authorization headers. Deploy both the UI and API before linking this route from the company website; no database migration or separate website job upload is needed.

The directory contains currently open published postings for active clients with approved, correctly scoped requisition/JD sources and an available pinned application form. Published and Retired pinned form versions remain supported. Scheduled, expired, closed, filled, application-limit-reached and invalid-source postings are excluded. Existing certification-proof validation remains authoritative where configured. The response is not cached; the page refreshes on focus and every two minutes while visible. Application acceptance is checked again by the existing public application flow.

Cards show advertised title/reference, client, location, experience, raw salary/CTC range and currency, employment/work mode, vacancies and public job description details. Salary values use the same requisition-first fallback as internal job cards. There is no source salary-period field, so the directory does not invent monthly/annual/LPA units. Internal IDs, budgets, applicant/panel counts, recruiter contacts, approval data and application forms are excluded from the explicit public DTO.

Search and filters are shareable URL parameters. View details opens a read-only drawer. Apply follows the posting's existing generated public URL and does not create a new application session or change the published link. Existing `/careers/:slug`, verification, parsing, tracking and submission endpoints remain unchanged.

Validation: `PublicRecruitmentJobDirectoryTests` covers listing eligibility, pinned form versions, public data boundaries, narrative handling and application URLs; `payroll-ui/tests/public-jobs-board.test.mjs` covers search/filter behavior, raw salary units, sorting and exact safe application destinations. Frontend build and desktop/tablet/mobile browser checks cover the page. The implementation was smoke-tested using existing published records through a private loopback read-only host with no application startup/migrations, background workers, job publishing, candidate creation or email sending.
