# Public careers directory

`/careers` is the anonymous, all-client job board. It is outside `AuthGate` and uses `GET /api/public/recruitment/jobs` plus the existing public organization-brand endpoint. Both board requests omit cookies and authorization headers. Deploy both the UI and API before linking this route from the company website; no database migration or separate website job upload is needed.

The directory contains currently open published postings for active clients with approved, correctly scoped requisition/JD sources and an available pinned application form. Published and Retired pinned form versions remain supported. Scheduled, expired, closed, filled, application-limit-reached and invalid-source postings are excluded. Existing certification-proof validation remains authoritative where configured. The response is not cached; the page refreshes on focus and every two minutes while visible. Application acceptance is checked again by the existing public application flow.

Cards show GA Digital as the employer, the advertised role, a neutral job reference, posting geography, experience, raw salary/CTC range and currency, employment/work mode, vacancies and public job description details. The anonymous directory and individual application landing page use a shared presentation projection to replace the source client name/code in displayed JD text and form labels. Site labels remove client/institute prefixes while retaining the named posting geography. There is no public client filter; old `client` query parameters are discarded. This display rule derives from each job's client identity and also covers future clients. It does not modify internal records, approved JD versions, form/option IDs, submitted answers, application/tracking references or public application URLs. It is a display rule, not a claim that the existing public API responses are anonymized.

Salary cards use the owner's 17 November 2026 standard: annual salary, with currency and `/ year` stated explicitly. Existing structured salary/CTC ranges remain the first source and are displayed on that annual basis. When those amounts are empty, explicitly labelled monthly remuneration in the saved approved JD is multiplied by 12 for annualized comparison. An additional stated HRA percentage is included; a percentage inside a breakdown of an already stated total is not added twice. Unspecified `+ HRA` stays separate. Source JD text is retained, and annualized salary is not a promise of a full year's payment for a shorter project or a computed total employer-cost CTC. Project budgets are never used as per-person salary. Experience falls back to the saved JD's essential eligibility, retaining alternative qualification routes and excluding degree durations or desirable experience. Internal job cards receive the existing approved `JobDescriptionText` through the open-position DTO; no migration or stored-data update is required.

Internal IDs, budgets, applicant/panel counts, recruiter contacts, approval data and application forms are excluded from the explicit directory DTO.

Search and filters are shareable URL parameters. View details opens a read-only drawer. Apply follows the posting's existing generated public URL and does not create a new application session or change the published link. Existing `/careers/:slug`, verification, parsing, tracking and submission endpoints remain unchanged.

Validation: `PublicRecruitmentJobDirectoryTests` covers listing eligibility, pinned form versions, public data boundaries, narrative handling and application URLs; `payroll-ui/tests/public-jobs-board.test.mjs` covers search/filter behavior, raw salary units, sorting and exact safe application destinations. Frontend build and desktop/tablet/mobile browser checks cover the page. The implementation was smoke-tested using existing published records through a private loopback read-only host with no application startup/migrations, background workers, job publishing, candidate creation or email sending.

The 48 source ICMR records all produce a remuneration display and an experience statement; six explicitly have no minimum experience stated in essential eligibility. Read-only local browser checks covered all 52 listed jobs, a detail drawer, an application landing page, and approximately 391/768/1365 CSS-pixel widths without horizontal overflow. The UI build and API compile passed.
